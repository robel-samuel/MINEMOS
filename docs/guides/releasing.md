# Releasing to PyPI

MINEMOS is published to [PyPI](https://pypi.org/project/minemos/) through
[Trusted Publishing](https://docs.pypi.org/trusted-publishers/) from the
`robel-samuel/MINEMOS` repository. The release workflow is
`.github/workflows/publish.yml`; it authenticates with a short-lived GitHub
OIDC token, so no PyPI API token or password is stored in the repository or in
GitHub secrets.

The workflow builds the wheel and source distribution, verifies that the
artifact names match the version in `pyproject.toml`, runs
`twine check --strict`, and uploads with the official
`pypa/gh-action-pypi-publish@release/v1` action. PEP 740 attestations are
generated by default.

## One-time setup

These steps must be performed by the repository owner; they cannot be done
from CI or from the repository itself.

### 1. Register the pending trusted publisher

At <https://pypi.org/manage/account/publishing/> (Account settings →
Publishing), choose **Add a new pending publisher** and enter exactly:

| Field | Value |
|---|---|
| PyPI Project Name | `minemos` |
| Owner | `robel-samuel` |
| Repository name | `MINEMOS` |
| Workflow name | `publish.yml` |
| Environment name | `pypi` |

For the TestPyPI rehearsal, add the same pending publisher at
<https://test.pypi.org/manage/account/publishing/> with environment name
`testpypi`.

The first successful upload creates the project; the pending publisher then
becomes its trusted publisher. Any of these values changing later requires
updating the trusted publisher on PyPI as well.

### 2. Restrict the `pypi` environment

In GitHub → Settings → Environments, the `pypi` environment is created
automatically the first time the workflow references it. Restrict it under
**Deployment branches and tags** to `main` and the `v*` tag pattern, and
optionally add required reviewers. Do the same for `testpypi`.

The workflow job also refuses to run unless
`github.repository == 'robel-samuel/MINEMOS'`.

## TestPyPI rehearsal

1. Actions → **publish** → **Run workflow**, branch `main`, target
   `testpypi`.
2. Install the uploaded distribution in a clean Python 3.12 environment:

   ```bash
   python -m venv .venv-testpypi
   .venv-testpypi/bin/python -m pip install \
     --index-url https://test.pypi.org/simple/ \
     --extra-index-url https://pypi.org/simple \
     minemos==0.1.1
   ```

   TestPyPI does not host the runtime dependencies, so the extra index resolves
   them from PyPI.
3. Verify the import paths, metadata, licence files and quick start as
   described in [Installation](installation.md).

## Publishing a release

1. Confirm `version` in `pyproject.toml`.
2. Merge to `main` with the `tests` workflow green.
3. Create a GitHub release with tag `v<version>` (for example `v0.1.1`). The
   published release triggers the `publish` workflow on the release commit, and
   the build job rejects a tag that does not match the package version.
   Alternatively, run the workflow manually with target `pypi`.
4. Verify the result:

   ```bash
   pip index versions minemos
   pip install minemos
   ```

## If a publish fails

Read the Actions log before making changes. Typical causes:

- `invalid-publisher` / 403: the pending trusted publisher does not match the
  owner, repository, workflow filename or environment name.
- `401` at upload: the job is missing `id-token: write` or is not running from
  this repository.
- `File already exists`: that version was already uploaded. A released version
  cannot be replaced; a new version is required.

Do not change the version to work around a configuration failure — fix the
publisher configuration first.
